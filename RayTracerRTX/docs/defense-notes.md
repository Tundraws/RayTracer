# Defense notes

Этот файл помогает быстро подготовиться к защите проекта. Он не заменяет пояснительную записку, а собирает в одном месте цель, реализованные требования, сценарий показа и честные ограничения.

## Краткая цель проекта

RayTracerRTX - учебная система рендеринга трёхмерных сцен в реальном времени на C++ с использованием CUDA, NVIDIA OptiX и аппаратной RTX-трассировки лучей.

Проект показывает:

- интерактивную камеру;
- освещение и тени;
- отражающие, матовые, металлические и стеклянные материалы;
- загрузку полигональных сеток из OBJ/MTL;
- ограниченный импорт glTF;
- режим накопления сэмплов;
- дополнительный шумоподавитель OptiX;
- настройку экспозиции, яркости неба и яркости света;
- тесты, замер производительности, Docker-проверку и документацию.

## Что показать на защите

1. Запустить стандартную сцену:

```powershell
.\x64\Debug\RayTracerRTX.exe
```

2. Показать управление камерой:

- `W/A/S/D` - движение;
- мышь - поворот камеры;
- `J/L`, `I/K`, `U/O` - движение света.

3. Показать переключение сцен:

- `G` - смена демонстрационной сцены или модели.

4. Показать материалы:

- `M` - смена материала сферы;
- `B` - выбор следующего mesh-объекта;
- `V` - смена материала выбранной сетки.

5. Показать режимы качества:

- `Q` - Low / Medium / High / PathTracing.

6. Показать режим накопления:

- `P` - переключение режима реального времени и режима накопления;
- `N` - включение или выключение шумоподавителя.

7. Запустить отдельные сцены:

```powershell
.\x64\Debug\RayTracerRTX.exe --scene RayTracerRTX\assets\scenes\textured_cube_scene.json
.\x64\Debug\RayTracerRTX.exe --scene RayTracerRTX\assets\scenes\multi_mesh_scene.json
.\x64\Debug\RayTracerRTX.exe --scene RayTracerRTX\assets\scenes\gltf_scene.json
```

8. Показать тесты и замер производительности:

```powershell
RayTracerRTX\tests\x64\Debug\RayTracerRTX.Tests.exe
RayTracerRTX\tests\x64\Debug\RayTracerRTX.Tests.exe --benchmark
```

9. Показать Docker-проверку:

```powershell
docker compose build --no-cache
docker compose run --rm coursework-check
```

## Честные ограничения

- OBJ поддерживается не полностью, а в нужном для проекта наборе: вершины, нормали, текстурные координаты, треугольные грани, MTL-материалы.
- MTL поддерживает только используемые параметры: `Kd`, `Ks`, `Ns`, `Ni`, `d`, `map_Kd`, `bump`, `map_Bump`, `norm`.
- glTF поддерживается в простом варианте: `.gltf` + внешний `.bin`, геометрия, базовые материалы и простые преобразования.
- `.glb`, анимации, скелетная анимация и сложные карты текстур glTF сейчас не поддерживаются.
- Карта нормалей меняет только направление нормали при освещении, но не меняет геометрию.
- Режим накопления улучшает изображение со временем, но может быть шумным при движении камеры.
- Шумоподавитель OptiX является дополнительной возможностью: если он недоступен, программа продолжает рендеринг без него.
- Docker-проверка не запускает GPU/OptiX окно, потому что контейнер предназначен для CPU-only проверки структуры, assets и тестов.

## Короткий ответ на вопрос о материалах

В проекте реализована учебная физически мотивированная модель материалов. Для прямого освещения используется GGX/Trowbridge-Reitz модель, а параметры MTL преобразуются в цвет, зеркальность, шероховатость, показатель преломления и прозрачность. Это достаточно для демонстрации подхода к материалам в трассировщике лучей, но поддерживается только описанный набор параметров.

## Короткий ответ на вопрос о режиме накопления

В обычном режиме программа старается быстро выдавать стабильный кадр. В режиме накопления renderer постепенно усредняет несколько сэмплов для каждого пикселя. Когда камера неподвижна, картинка становится чище. При движении камеры накопление сбрасывается, чтобы не смешивать старый кадр с новым видом.
