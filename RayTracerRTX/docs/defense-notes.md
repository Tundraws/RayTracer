# Заметки для защиты

Документ используется для быстрой подготовки к защите проекта. Он не заменяет пояснительную записку, а фиксирует цель, реализованные требования, сценарий демонстрации и ограничения.

## Краткая цель проекта

RayTracerRTX – учебная система рендеринга трёхмерных сцен в реальном времени на C++ с использованием CUDA, NVIDIA OptiX и аппаратной RTX-трассировки лучей.

Проект демонстрирует:

- интерактивную камеру;
- освещение и тени;
- матовые, зеркальные, металлические и стеклянные материалы;
- загрузку полигональных сеток OBJ/MTL;
- ограниченный импорт glTF/GLB;
- режим накопления сэмплов;
- шумоподавитель OptiX;
- настройку экспозиции, яркости неба и яркости света;
- тесты, измерение производительности, Docker-проверку и документацию.

## Требования и реализация

| Требование | Реализация |

| Вариант 42: трассировщик лучей в реальном времени | интерактивное приложение с OptiX/CUDA-рендерером и выводом через GLFW/OpenGL |
| C++ + CUDA + OptiX | CPU-код написан на C++, GPU-часть использует CUDA и OptiX |

| Интерактивное изменение сцены | перемещение объектов, добавление/удаление сфер, изменение материалов, качества, режима накопления и шумоподавителя |

## Сценарий демонстрации

1. Запустить стандартную сцену:

```powershell
.\x64\Debug\RayTracerRTX.exe
```

2. Показать управление камерой:

- `W/A/S/D` – движение;
- мышь – поворот камеры;
- `Shift` – ускорение движения.

3. Показать переключение сцен:

- `G` – смена демонстрационной сцены;
- `C` – сброс камеры и света текущей сцены.

4. Показать материалы и редактор:

- `M` – смена материала сферы;
- `B` – выбор следующего mesh-объекта;
- `V` – смена материала выбранной сетки;
- правая панель Dear ImGui – добавление, удаление и изменение объектов.

5. Показать режимы качества:

- `Q` – Low / Medium / High / PathTracing.

6. Показать режим накопления:

- `P` – переключение режима реального времени и режима накопления;
- `N` – включение или выключение шумоподавителя OptiX.

7. Показать настройку изображения:

- `4/5` – экспозиция;
- `6/7` – яркость неба;
- `8/9` – яркость света.

8. Запустить отдельные сцены:

```powershell
.\x64\Debug\RayTracerRTX.exe --scene RayTracerRTX\assets\scenes\textured_cube_scene.json
.\x64\Debug\RayTracerRTX.exe --scene RayTracerRTX\assets\scenes\multi_mesh_scene.json
.\x64\Debug\RayTracerRTX.exe --scene RayTracerRTX\assets\scenes\material_showcase_scene.json
.\x64\Debug\RayTracerRTX.exe --scene RayTracerRTX\assets\scenes\path_tracing_demo_scene.json
.\x64\Debug\RayTracerRTX.exe --scene RayTracerRTX\assets\scenes\gltf_scene.json
```

9. Показать тесты:

```powershell
RayTracerRTX\tests\x64\Debug\RayTracerRTX.Tests.exe
```

10. Показать Docker-проверку:

```powershell
docker compose build --no-cache
docker compose run --rm coursework-check
```

## Ограничения

- OBJ поддерживается в используемом проектом наборе: вершины, нормали, текстурные координаты, треугольные грани и MTL-материалы.
- MTL поддерживает параметры `Kd`, `Ks`, `Ns`, `Ni`, `d`, `map_Kd`, `bump`, `map_Bump`, `norm`.
- glTF/GLB поддерживается в ограниченном виде: `.gltf` + внешний `.bin` или `.glb` с JSON/BIN-частями, геометрия, базовые материалы, базовые текстуры и преобразования узлов.
- Анимации, скелетная анимация, morph targets, embedded base64 buffers, node matrix и сложные расширения glTF не поддерживаются.
- Карта нормалей меняет направление нормали при освещении, но не изменяет геометрию.
- Режим накопления очищает изображение при неподвижной камере, но при движении камеры накопление сбрасывается.
- Шумоподавитель OptiX является дополнительным режимом: при недоступности рендеринг продолжается без него.
- Docker-проверка не запускает GPU/OptiX-окно, так как контейнер предназначен для CPU-only проверки структуры, ресурсов и тестов.

## Ответ о материалах

В проекте реализована учебная физически мотивированная модель материалов. Для прямого освещения применяется GGX/Trowbridge-Reitz модель, а параметры MTL преобразуются в цвет, зеркальность, шероховатость, показатель преломления и прозрачность. Набор параметров ограничен задачами проекта.

## Ответ о режиме накопления

В режиме реального времени программа рассчитывает текущий кадр без накопления предыдущих результатов. В режиме накопления рендерер постепенно усредняет несколько сэмплов для каждого пикселя. При неподвижной камере изображение становится менее шумным. При изменении камеры накопление сбрасывается, чтобы старые сэмплы не смешивались с новым видом сцены.
